# 2026-10-31 业务可靠性与权限改造

## 已实现并验证的基础改造

1. 采购/销售创建、审批、重提和仓库处理改为事务；库存、流水、明细完成数量、应收应付、单据状态及业务历史一起提交。
2. 库存操作、退换货、盘点复核、基础资料申报和收付款使用同一事务入口。库存数量写入统一到 BusinessSupport::stock，锁定商品/仓库库存行并检查非负及溢出。
3. 同一单据的处理先锁定单据行，重复处理返回冲突。单据创建和付款支持 request_id / Idempotency-Key；同用户同请求键同内容重试返回原结果，不同内容使用同键会被拒绝。
4. 请求键与业务结果在同一事务保存。失败时请求键也回滚，可修正后重试。旧客户端不携带请求键时仍可调用，但不享受创建请求去重。
5. 金额在业务计算中使用整数分，拒绝超过两位小数、负数单价、非法日期和超付。
6. 退货检查原单商品、数量及包含待审批退货的累计数量，退入价格取自原订单；当前仅支持等价换货，拒绝不等价换货。
7. 盘点账面数量从数据库核对；复核前库存发生变化则整单拒绝调整。复核人为仓库领导且不能是原盘点/发起人。
8. 盘点单新增 counted_by，创建时自动记录当前登录人为盘点人，不接受客户端冒用其他人；reviewed_by 独立记录复核人。旧单据不推测补写盘点人。
9. JWT 每次请求查询当前账号、角色和部门。通用基础资料接口要求登录，员工变更走申报；单据列表、详情与明细在后端按本人、部门及仓库限制范围。
10. 禁止自审；只有发起人可以修改重提。采购与销售重提会清除当前轮次旧审批/仓库标记，历史动作保存在 business_events。
11. 旧直接出入库接口停止注册；批量导出暂限管理员。财务明细仅管理员/财务可查看。权限管理菜单、页面和维护接口已移除，业务角色校验继续执行。
12. 采购/销售、仓库处理和申报详情可查看处理历史。操作日志记录实际响应状态及耗时。
13. 首页安全库存预警与库存流水原先未赋值，现使用后端聚合统计；规则统一为 quantity <= min_quantity。首页15秒刷新并支持预警记录跳转，仓库员工仅统计所属仓库，仓库领导统计管理范围。

## 迁移与部署

已有 ERP 数据库执行 `python3 db/migrate_reliability.py`，会创建 business_events/business_requests，并增加盘点复核人和盘点人字段。不会删除旧表或改写历史业务数据。此前迁移仍按 deploy/README.md 执行。

本地 WSL 的 127.0.0.1:3306 在本次启动中指向了失效转发，已将本地 config.json 与 build_wsl/config.json 的主机更新为验证可连的本地 MySQL 容器地址 172.17.0.2。生产容器仍由部署环境变量 DB_HOST 配置。

后端标准构建：`cmake -S . -B build_wsl && cmake --build build_wsl -j2`。本地为减轻 Windows 目录链接开销，CMake 运行输出临时指向 /tmp/erp-system-runtime，验证后将最新可执行文件复制回 build_wsl。
