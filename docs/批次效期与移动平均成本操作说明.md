# 商品批次效期与移动平均成本

## 商品设置

管理员在商品维护中按商品开启批次管理。启用有效期管理时必须同时开启批次管理；已有批次历史不能直接关闭批次管理。已有在库批次缺少日期时，不能直接开启有效期管理，须先核实历史资料。

日期按自然日判断，有效期当天仍可正常使用，早于数据库当前日期则视为过期。过期批次不能用于普通销售和普通调整出库，管理员也受后端校验限制。备货时先检查未过期可用数量，最终放行时再次检查，防止备货后跨日过期。

## 历史库存初始化

商品启用批次管理且已有库存时，先进入商品批次库存页面，按实物资料登记期初批次。分配数量合计不得超过实物库存，分配操作本身不增加库存。批次数量合计与实物库存不一致时，后续批次过账会拒绝执行。

管理员在库存成本页面登记可核实的期初单位成本及依据，最多6位小数。系统检查库存快照，保存期初数量、单位成本、总价值和流水基线；已经初始化的记录不能通过该入口再次覆盖。未知历史成本不自动按商品当前成本价或零成本补算。

## 收发与调拨

批次商品的分批采购入库须填写批次号。有保质期商品同时填写生产日期和有效期；日期必须真实合法，生产日期不能晚于有效期。同一商品、仓库、批次号再次入库时日期必须一致。

普通销售自动优先使用有效期较早的可用批次，无有效期批次排在后面；过期数量不参与普通出库。备货预占仍在商品仓库层面进行，最终放行重新分配有效批次，并将实际批次扣减、数量和成本快照放入同一事务。

库存调整入库可填写批次、日期和单位成本；未填写可核实成本时明确标记成本未知。调拨保持来源批次号、日期及实际转出成本，跨仓库库存价值保持一致。当前调拨仍是同一事务内调出调入，不包含在途签收。

销售退货依据原销售出库批次恢复数量；成本来源于原订单已保存的出库成本快照按实际原出库数量计算。缺失历史批次资料时不会虚构批次，缺失成本记录时不会假设为零。退货涉及多次不同成本发货时，采用原订单已出库成本的加权单位成本，而不是当前商品成本价。

过期商品需要处置时，在库存调整中选择出库、业务类型报损，填写原因，由另一位授权人员审批。报损会记录实际扣减的批次和成本。采购退货及经审批调拨可以处理过期批次，但不会让其变成可销售批次。

## 成本与毛利

移动平均按商品和仓库核算。采购入库使用订单实际批次金额增加库存价值；出库从当前库存价值按数量比例分摊，保留6位小数；最后一笔清空数量时一并结清库存价值尾差。后续修改商品资料不会重算既有出库成本快照。

报表毛利使用已过账销售净额减对应出库成本，并考虑退货成本冲回。任何相关历史销售或退货成本缺失、账目缺少可关联出库流水时，显示历史成本待补全，不使用销售额减采购额冒充毛利。当前期初成本录入不会凭空补出历史交易成本。

## 部署与验证

已有库在此前迁移后执行 db/migrate_lots.py、db/migrate_costing.py。测试脚本 test/verify_lots_costing.py 覆盖批次与日期必填、非法日期、过期备货拦截、备货后过期的放行回滚、移动平均成本、审批报损、调拨成本及批次保持、原单销售退货、历史批次分配、低单价期初成本及禁止覆盖。

生产服务器镜像需要重新打包后才能包含本轮改造。此功能不等同于序列号逐件台账，也不代表自动异机备份配置、在途调拨、打印对账及服务器容量验收已完成。
