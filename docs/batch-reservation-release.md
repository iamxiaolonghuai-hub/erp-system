# 分批收发与预占库存

2026年10月31日改造。已有数据库先执行 db/migrate_operations.py，再执行 db/migrate_batches.py，创建预占字段、备货批次数量、独立收发批次及报表视图。两者均可重复执行。

迁移账号除 ALTER、CREATE 外，还需要 CREATE VIEW 权限。管理员可从 /inventory/fulfillment 进入分批收发审核；仓库领导与员工沿用各自的仓库审核页面。

## 操作规则

仓库审核列表新增分批入库、分批备货及放行本批入口。每行本批数量可在0与剩余数量间选择，0表示本批不处理。采购每批实际收货立即增加库存，累计应付仅增加该批金额；全部收完才完成原订单。

销售部门审批不预占。仓管员确认本批备货时预占，数量不得超过实物库存减其他预占。仓库领导放行时按备货数量释放预占、扣减实物库存、记录独立出库批次并累计应收。领导不能改动本批备货数量，需修改时先打回该批。订单部分发货后返回待备货，后续批次重复执行。

入库、出库和调拨等统一库存入口不允许消耗其他已预占库存。取消本批会释放该批预占；已有过账批次的单据不能作废或修改重提，保持原实物和账务记录。当前不提供部分订单剩余数量关闭功能。

所有批次请求带 request_id；同一请求重试返回原结果。库存、明细完成量、账目、批次及动作记录在同一事务内保存。金额按原订单单价逐批计算，现金和贷项抵扣不混作收入金额。

迁移前已处于待放行、但没有本批数量的旧销售单，不推测补占库存。应先打回，再由原发起人按原流程重提、重新备货；已有历史过账数据应先人工核对。

## 报表口径

全局财务报表以 accounts 中已经实际过账的购销金额为依据，不统计未收发的订单金额。退货金额和净额单独列示；应收应付只统计正向账目的未结余额，未处理退货贷项单独统计；余额扣除现金结算及抵扣。

部门金额与金额趋势使用实际收发批次的过账时间，兼容没有批次记录的历史账目。订单计数、商品订货件数等属于订单业务指标，不等同于实际出库数量。毛利不再使用销售额减采购额冒充，缺少成本核算时明确不输出金额。
