# ERP 角色功能与业务逻辑审查

审查日期：2026-11-09。依据当前工作区的菜单、路由、接口和业务服务。前几节记录整改前的代码核对与流程推演，末节记录本轮完成的整改和验收。

## 角色与职责

登录账号、员工档案、所属部门和所属仓库各有用途。部门从主档选择，员工档案与关联账号调度同步；调离仓库部时清除原仓库。管理员保留用户、部门和调度功能，没有独立权限管理菜单。部门管理可新增、维护、启停及删除，但四个内置业务部门受保护，新增组织部门不会自动获得采购、销售、仓库或财务权限。

| 角色 | 日常模块 | 权限与交接 |
| --- | --- | --- |
| 管理员 | 经营首页、商品与分类、客户与供应商、员工与仓库、库存与盘点、分批收发、财务、用户、部门、日志、备份 | 可跨业务查看和处理；可按规则接管指定审批，仍受禁止自审和经办复核分离限制。部分订单及报表有路由但未纳入主菜单 |
| 采购员工 | 采购单、采购退货、供应商和商品申报、个人单据 | 发起时可选审批领导；获批后由仓库收货，财务处理应付 |
| 采购领导 | 部门工作台、采购和退货审批、供应商和商品申报审批、本部门员工 | 查看部门业务；指定给其他领导的单据通常不能代审 |
| 销售员工 | 销售单、销售退换货、客户申报、个人单据 | 获批后转仓库备货与放行，已过账销售形成应收 |
| 销售领导 | 部门工作台、销售及退换货审批、客户申报审批、本部门员工 | 审批销售业务，不替代仓库出库放行 |
| 仓库员工 | 库存和批次、采购收货、销售备货、库存调整与调拨申请、盘点 | 常规仓储操作限所属仓库；登录人记录为盘点人，备货后由另一位人员放行 |
| 仓库领导 | 仓储工作台、销售放行、库存调整审批、盘点复核、仓库维护和人员分配、处理历史 | 当前可跨仓库处理；不能审批自己发起的库存调整或复核自己的盘点 |
| 财务员工和领导 | 财务首页、往来账、收付款、退款、抵扣、冲正、财务复核、库存成本 | 共用财务工作台。资金动作由另一位财务人员或管理员复核后生效；当前没有把复核权限限定为财务领导 |

## 已有业务流程

| 模块 | 触发条件与结果 |
| --- | --- |
| 采购 | 发起 → 部门审批 → 仓库分批收货。每批更新库存、流水、收货批次和原订单应付；剩余数量可继续收货，符合条件时可关闭剩余 |
| 销售 | 发起 → 部门审批 → 仓库分批备货并预占 → 另一位授权人员放行。放行才扣实物库存、生成出库批次和应收；打回或关闭时按规则释放预占 |
| 退换货 | 按已完成或已关闭订单的实际收发量计算可退数量 → 部门审批 → 仓库处理实物。普通退货产生独立贷项；销售换货目前支持等价换货 |
| 库存、盘点 | 调整和调拨获批后执行库存流水；盘点记录盘点人，另一人复核差异；账面数量变化时阻止以旧快照调整 |
| 商品、批次与成本 | 商品选择供应商，可按商品启用序列号、批次和效期；启用效期的入库须填生产日期和有效期，过期库存不能普通销售，可走报损。成本按商品和仓库移动加权平均；缺历史成本需核实期初，不以零代替 |
| 财务 | 采购、销售按实收实发入账；应收应付和退货贷项分别展示。收付款、退款、抵扣和冲正经独立人员复核后过账，保留原记录 |
| 客户与供应商 | 维护、搜索、CSV 模板、导入、导出；导入按名称清理首尾空格和英文大小写后去重，跳过重复记录，不覆盖原档 |
| 审计与备份 | 单据记录发起、指定审批、实际处理、批准或复核等不同人员；关键操作保存业务事件。备份支持配置另一台服务器、定时和手动任务、传输校验、页面告警和服务日志；实际异机保护取决于目标配置与恢复演练 |

## 逻辑问题与建议

| 优先级 | 发现与影响 | 建议验收场景 |
| --- | --- | --- |
| P0 | **退换货缺仓库待办。** 仓库审核页只加载采购和销售订单，仓库侧边栏没有退换货入口；购销领导的退货页却可显示仓库确认按钮，服务层会按仓库权限拒绝。审批过了也可能没有人从正常菜单接单 | 仓库人员从工作台看到本仓待退入、待退出、待换货；购销领导只能做业务审批；跨仓操作被后端拒绝 |
| P0 | **退货原单权限需要补齐。** 创建退货的路径在后端按部门与原单状态、实发数量校验，未见按申请人校验原单可访问范围。界面列表的权限不应由直接提交原单 ID 绕过 | 使用两个销售员工隔离测试：无原单访问权的员工提交该原单 ID，返回无权操作；有明确代办权的人可正常提交 |
| P1 | **审批历史仍按订单当前字段查。** 仓库“我处理的”仅收录已完成订单，按最后经办或放行人、原订单号和最后更新时间筛选。购销“我批准的”按订单创建日期筛选，也不能代表历史批准时间。前一位放行人、部分完成及关闭订单会漏查 | 同一订单两批由不同人员收发；每人按实际时间、原单号或 IN/OUT 批次号都查得到自己的记录。购销按实际批准时间查，批准与驳回分开 |
| P1 | **员工调度缺待办交接。** 指定审批人调岗、离职或停用后，校验仍引用原指定人；管理员可接管部分审批，但调度时没有提示待办数量和移交入口 | 调度前显示受影响的待办，允许移交给符合资格的人并记录原人、接收人、操作者和时间；不改变已批准历史。调入仓库时可同时选仓库 |
| P1 | **序列号仅做到局部记录。** 库存调整会检查本次数量和重复，采购收货、销售发货及退货没有共用的单件台账。同一序列号可能跨单重复登记，无法可靠查询单件当前所在仓库或客户 | 启用序列号的商品每件收发都要登记；按商品与序列号做唯一校验，可反查收货、出库、退换和调拨 |
| P1（多仓时优先） | **调拨批准即同时扣源仓、加目标仓。** 实物运输中目标仓已经有账面库存；仓库领导也可跨仓操作 | 支持源仓发运、在途、目标仓签收，处理短收和拒收；负责人只能操作授权仓库 |
| P2 | **财务两人复核有了，但岗位边界与结账不完整。** 财务员工也可复核另一人的申请；报表主要是全量汇总，缺少按期间的往来对账和期末结账 | 由公司确定复核岗位或金额阈值；按期间核对期初、发生、收付、抵扣和期末，结果能追到原单 |
| P2 | **资料维护入口规则不同。** CSV 能去重，手工保存和审批转档没有共用同一规则；管理员商品页可配置批次效期，员工商品申报当前只保存序列号等基础设置 | 三个入口按同一业务规则识别往来单位；同名不同主体保留明确识别方式。申报和审批均展示批次及效期选项 |
| P2 | **安全库存和销售可用量是两个口径。** 当前预警用账面数量比较安全库存。预占量较多或只剩过期批次时，账面还充足但实际可销售量不足 | 保留现有账面预警；另列可用库存或可销售库存预警，标注是否扣除预占和过期批次，仪表盘和下钻列表用同口径 |
| P2 | **查单和导航缺少统一入口。** 管理员已有采购、销售、报表路由，主菜单没有对应入口；仓库历史等列表在客户端载入后筛选 | 按角色补齐采购、销售、退换货、报表入口；核心业务列表用服务端分页，筛选、导出和打印沿用同一查询条件 |

P0 表示正常业务链或关键数据权限存在缺口；P1 表示业务能运行，但会影响追踪、交接或特定经营场景；P2 表示管理效率和控制能力不足。优先完成退换货仓库待办和原单权限，然后一起做审批历史与调度交接。单仓、普通商品业务已有基础闭环；若经营序列号商品或经常跨仓调拨，对应的 P1 应列为正式使用前验收项。异机备份须以真实传输和独立恢复结果为准。

## 2026-11-09 整改与数据清洗

仓库菜单新增采购退货待出库、销售退换货待处理。待办按实际操作仓库过滤，退货发起时同时校验原单访问权限。购销领导审批页、仓库审核页、财务复核记录按本人动作查询，支持原单号、实际处理日期和收发批次号。历史数据以已有事件或批次为依据。

员工调度在保存前列出指定审批待办及可接收人员。待办移交、部门与仓库修改在同一事务内执行。单独移交适用于已经调离或停用的账号。停用、离职和删除账号前检查待办，订单和申报重提时原审批人失去资格的，进入部门审批队列并记录原因。
