# 数据库规范化与部门管理（2026-11-01）

## 管理员操作

“系统管理 → 部门管理”支持部门查询、新增、编辑、启停和删除。名称、编码不得重复；存在关联账号或员工档案的部门不能停用、删除，应先完成调度。四个系统业务部门的名称、编码和启用状态暂时保护，可修改说明；新增组织部门不会自动获得采购、销售、仓库或财务的业务权限。

“系统管理 → 员工调度”改为按部门ID选择。调度前确认原部门与目标部门，保存时账号与关联员工档案在同一事务内同步。调离仓库部会清除账号的原所属仓库。重复调度到相同部门不会误报账号不存在。

“基础资料 → 员工管理”使用部门下拉框，不再手敲名称。可为新档案或尚未关联账号的档案选择已有登录账号，自动带出该账号的部门等资料；一个账号只能关联一份员工档案。已有绑定不能直接改绑。账号可先在“用户管理”创建。离职会停用关联账号，恢复在职不会自动启用账号，需管理员另行确认启用。

页面切换时重新查询当前登录身份，更新部门和角色，避免调度后继续使用本地缓存的旧菜单。服务端仍独立验证每次请求的当前权限。

发起人转部门后，已有客户、供应商或商品申报仍按原业务类型的审批部门处理，不会因当前人员部门变化而切换旧申报的审批归属。多角色账号在调度列表只显示一行。

## 已实施的数据结构调整

| 结构 | 当前规则 |
| --- | --- |
| `users.department_id`、`employees.department_id` | 外键关联部门主表；原`department`文字列已移除 |
| `user_directory`、`employee_directory` | 查询视图，将部门ID关联为名称，兼容接口的展示字段；不重复保存名称 |
| `employees.user_id` | 唯一关联账号，外键保护；账号删除时保留员工档案并解除关联 |
| `stock_operation_serials` | 每个序列号独立一行，保留单内顺序，拒绝同一操作单内重复；原CSV字段已移除 |
| `order_delivery_items` | 分批收发独立商品行，保存数量和成交单价；原JSON业务明细列已移除 |
| 采购、销售退货 | 从原订单关联往来单位；原重复供应商/客户ID列已移除，接口仍返回关联计算出的字段 |
| 单据行与盘点差异 | 数据库约束校验数量、价格、小计，以及实盘减账面等于差异，拒绝独立写入不一致值 |

成交单价、出库成本及审计快照保留历史语义。库存、预占、订单金额等汇总仍由业务事务维护并进行一致性审计，不能宣称全库没有任何冗余。序列号逐条存储也不等于已经完成跨全部购销、退货、调拨的唯一序列号生命周期管理。

## 迁移及数据保护

先备份数据库及附件，再停止ERP业务写入。迁移应与配套后端同时升级，旧后端不能直接运行在移除旧列后的数据库上。

```sh
docker compose run --rm --no-deps backend python3 db/migrate_departments.py --check-only
docker compose run --rm --no-deps backend python3 db/migrate_normalized_details.py --check-only
docker compose run --rm --no-deps backend python3 db/migrate_departments.py
docker compose run --rm --no-deps backend python3 db/migrate_normalized_details.py
```

前两条只预检，不改数据。遇到账号重复关联、历史收发明细无法确认价格、退货往来单位不符、金额或盘点差异不一致等情况会拒绝迁移，不虚构数据。

账号与员工原部门不一致时，以现有账号部门保留权限归属，旧值保存在`employee_department_migration_log`。原始部门文字另存于`department_legacy_labels`。关联账号已不存在的员工档案保留，原无效账号ID记入`employee_account_repair_log`后解除关联，管理员可重新选择账号。原CSV、JSON及退货重复字段保存在`normalization_archive`。

迁移可重复执行，新的业务明细不会因重复运行而被清空。恢复工具已加入两个目录视图的跨库重建规则，避免恢复环境查询原业务数据库。
