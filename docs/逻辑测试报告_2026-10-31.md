# ERP 业务逻辑测试报告

测试日期：2026年10月31日。对象为当前本地运行版本，不是此前生成的服务器离线镜像包。

## 结论

现有六组业务验证脚本顺序运行通过。补充的收付款与退款现金冲正测试通过；实际数据库十项只读一致性检查均为零异常。此次未发现所覆盖范围内的逻辑失败，不代表所有业务场景均无缺陷，也不替代生产容量压测和真实业务验收。

## 已验证流程

| 范围 | 验证结果 |
| --- | --- |
| 分批采购收货 | 部分收货保持待处理，实际数量、账目和批次同步；同请求并发重试只过账一次 |
| 销售预占与放行 | 并发争抢仅足量订单成功；分批发货、重复放行、作废释放正常；其他出库不能消耗已预占数量 |
| 事务回滚 | 非法第二行、库存不足、调拨目标失败时，不遗留部分库存和账务变动 |
| 财务复核 | 提交不改账、自审拒绝、并发审核不超额收付；请求重试去重 |
| 退款和抵扣 | 退款、同单位抵扣、抵扣冲正正常 |
| 现金冲正 | 收款和退款冲正恢复相应余额，原记录保留，重复冲正被拒绝 |
| 撤回与作废 | 撤回后可重提，作废后不能继续审批 |
| 盘点 | 不允许冒用盘点人；复核人与盘点人分离；库存快照过期时拒绝调整 |
| 退货量价 | 超量退货拒绝；退回价格以原单为准，不能由客户端随意改价 |
| 权限 | 越权列表、详情、直接写入、伪造角色及自审被拒绝；指定审批人正常保存 |
| 资料导入导出 | 中英文表头、重复上传、并发去重、错误行和CSV往返内容验证通过 |
| 报表 | 全局已过账金额与账目汇总一致；不再输出错误的占位毛利 |

验证脚本：verify_batches_concurrency.py、verify_reliability.py、verify_finance_actions.py、verify_lifecycle.py、verify_partner_import.py、verify_product_approvals.py，均位于 test 目录。整套运行日志保存在 build_wsl/logic-audit.log；补充现金冲正及只读检查已另行运行通过。

## 实际数据只读检查

以下检查均返回零条异常，未修改现有记录：

1. 实物库存负数、预占负数或超过实物量。
2. 库存预占不等于待放行批次合计。
3. 销售已发数量或本批数量越界。
4. 采购已收数量越界。
5. 非待放行销售单残留本批数量。
6. 正金额账目的现金及抵扣方向、额度异常。
7. 退货贷项的现金及抵扣方向、额度异常。
8. 已结清状态与实际余额不一致。
9. 财务申请由经办人自己复核通过。
10. 已过账批次合计与对应账目金额不一致。

可重复执行 `python3 test/audit_business_consistency.py`。检查应在没有其他测试临时数据干扰时进行；正常营业期间跨表检查可能受同时发生的业务影响，需要结合事务时间复查。

## 测试数据与边界

写入验证只使用唯一标记的临时商品和单据，已执行脚本清理；接口审计日志与部分请求去重记录可能保留。未用真实订单测试收发和收退款，也未访问银行或执行真实转账。

本次没有重新执行备份恢复演练，其独立数据库及附件恢复演练结果见 backup-restore-guide.md 对应工具和 test/verify_backup_restore.py。本次没有进行浏览器逐页面人工验收、长时间压力测试、断电或数据库断连故障注入。

后续上线仍需核对期初库存和往来账、更新离线镜像、在腾讯云实际配置下验收，并用公司的真实典型流程进行业务签收。
