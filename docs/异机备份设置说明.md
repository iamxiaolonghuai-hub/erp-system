# 异机备份设置与宿主机任务

管理员在系统管理的异机备份设置中填写目标服务器、SSH端口、用户名、远端目录、宿主机私钥路径、本地目录、北京时间每日计划和本地保留份数。这里不接收私钥内容或数据库密码。

保存配置只改变策略，不代表连接成功或已经备份。页面区分待执行、执行中、失败或取消、完成远端校验；近期没有宿主机任务心跳时显示提示。按用户选择，失败通知仅使用页面告警和服务器日志，不发送邮件或外部消息。

## 执行与清理规则

宿主机执行器每五分钟检查手动任务和每日计划。计划每天尝试一次，失败后不反复触发，应查看原因并手动重试。备份期间停止指定ERP后端以暂停写入，导出数据库及附件后恢复原本运行的后端。数据库还有其他写入程序时，需要运维同步暂停它们。

SSH始终校验主机指纹，不自动接受未知主机。传输完成后检查远端SHA256，只有校验一致才记为成功并按保留份数清理旧本地归档；传输失败保留本地文件，远端不自动删除。源目录中的其他文件不参与清理。

修改配置会取消原先还未执行的排队任务；已开始的任务按领取时配置继续完成。禁用自动备份不强行中断已经开始的数据库导出。

## 安装前提

以下命令针对服务器ERP部署目录 /opt/erp，需要先完成ERP及数据库迁移。新的部署必须包含 deploy/backup_job.py、deploy/data_backup.py 和 systemd模板。旧离线镜像包或仅复制一个Python文件不能视为已完成安装。

先执行 db/migrate_backup_settings.py。宿主机需要 Python 3.9或以上、Docker CLI、Docker Compose、OpenSSH客户端。准备专用备份SSH私钥，目标服务器配置对应公钥和备份目录权限；私钥保存在宿主机且权限为600，不要放入公开附件目录。

用实际登录账户手动核对目标服务器指纹并建立 known_hosts；定时任务默认以root运行，因此需要确保root的SSH配置和known_hosts可用。不能通过关闭StrictHostKeyChecking解决连接失败。密钥若加密，应自行配置可用于非交互任务的ssh-agent，否则任务会失败。

## 安装定时任务

确认 /opt/erp/.env 已正确填写 DB_HOST、DB_NAME、DB_USER、DB_PASSWORD；EnvironmentFile由systemd读取，不要将真实密码填进页面或命令历史。

```sh
cd /opt/erp
sudo mkdir -p /opt/erp/state
sudo chmod 600 .env
sudo cp deploy/erp-backup.service /etc/systemd/system/erp-backup.service
sudo cp deploy/erp-backup.timer /etc/systemd/system/erp-backup.timer
sudo systemctl daemon-reload
sudo systemctl enable --now erp-backup.timer
sudo systemctl start erp-backup.service
sudo systemctl list-timers erp-backup.timer
```

任务默认通过Compose定位唯一后端容器。若部署目录或服务命名不同，应修改service中的WorkingDirectory及ExecStart。需要显式指定后端容器或镜像时，在EnvironmentFile中填写 ERP_BACKEND_CONTAINER、ERP_BACKEND_IMAGE。DB_HOST若只是网络别名而非实际MySQL容器名，可额外设置 BACKUP_MYSQL_CONTAINER。

数据库用户需要读取业务表和视图、导出、以及写入备份配置及任务表的权限。任务不会导出其他数据库，也不会将.env、数据库密码或SSH私钥放进归档。

## 验收与日志

先保存目标配置，再提交立即备份，然后等待执行器领取。需要立即检查队列可执行：

```sh
sudo systemctl start erp-backup.service
sudo journalctl -u erp-backup.service -n 100 --no-pager
```

通过标准是：任务显示完成远端校验，目标服务器确实存在对应归档，且恢复演练能核对数据库和附件。页面显示已保存、已排队或任务心跳在线均不等于异机备份成功。

## 恢复保护

每个ERP实例只部署一个宿主机执行器。备份暂停后端前，会保存受保护的恢复标记；正常结束或失败时会重新启动原本运行的后端。进程被强制终止或宿主机重启后，下次执行器启动会先处理恢复标记，再领取新任务，并把遗留的执行中任务标记为失败。恢复标记默认位于 `/opt/erp/state/backup-recovery.json`，请勿手动删除。服务器重启至下一次执行器运行之间仍可能存在短暂不可用，应结合服务日志确认恢复。

新版备份单独保存视图定义。跨库恢复会重建ERP报表视图指向目标库，拒绝未经核对的额外自定义视图或残留源库引用，避免测试环境误读原业务库；视图采用恢复账户权限下的SQL SECURITY INVOKER。旧版含视图备份不能直接跨库恢复。

恢复后自动禁用已恢复的自动备份配置，并取消历史排队或执行中任务，防止恢复环境沿用旧任务向原目标传输数据。验收并核对目标地址、密钥、数据库配置后，由管理员重新启用。

工具目前一次在内存中处理归档，适用于当前小规模数据；大数据量需要进一步改成流式处理及评估停机窗口。实际目标服务器还未填写并验证时，不应认定异机备份已经投入运行。
